# Profile synchronization

Run `python3 tools/u1/profile_sync.py --source orca=/path/to/orca --source forca=/path/to/forca --source snapmaker-profiles=/path/to/pinned-profile-repo --destination /new/catalog`.

Inputs are read-only Git checkouts whose HEAD must match tools/u1/sources.lock.json. Tracked or untracked preset edits are rejected. Snapmaker's current active presets come from the exact submodule gitlink, not its partly empty resources/profiles directory. Default vendors are Snapmaker and OrcaFilamentLibrary; repeat `--vendor` for other bundles and include their inheritance dependencies. No default material is declared calibrated for U1.

The tool creates immutable source+SHA snapshots containing original byte-preserved profiles, indexes and auxiliary assets. An attributed manifest stores source URL, commit, license label, content hashes, scoped identities and inheritance. Exact repeated index entries are counted; conflicting identities are rejected. Cross-source collisions are reported and resolved by source namespaces, without renaming presets and breaking their internal references. Repeated runs verify existing snapshot hashes and refuse tampering. `current.json` is replaced atomically after successful snapshot generation.

This is a **review catalog**, not an installed preset bundle. It preserves original inheritance and source indexes; it does not flatten settings or modify resources/profiles. User overrides belong in a separate user-owned location and are never touched. Existing non-empty unmanaged destinations and symlink escapes are refused. Source files and snapshots are not automatically licensed for redistribution. The separate Snapmaker profile source lacks an explicit license at the audited pin; do not ship that catalog before clarification.

Validation currently covers JSON duplicate keys, indexed identity/type, safe paths, scoped inheritance/includes, cycles, SHA pins and immutable hashes. Some legitimate base files omit `type`; index membership supplies it. It does **not** certify all option names/types against ConfigDef, array dimensions, firmware compatibility, material temperatures, mechanical limits or calibration. All imported presets are marked unvalidated. The existing official `scripts/orca_profile_tool.py` and compiled profile validator must pass before any compatible selection is promoted to the shipped bundle, with a bundle version bump.

PLA, PETG, TPU, ABS, ASA, PC, PA and composites are available only insofar as upstream sources supply corresponding presets; availability is not U1 calibration or safety approval. Exact material coverage and nozzle variants must be reported from catalog manifests, not assumed. Automatic import of existing user presets is not implemented; a future importer must be read-only and preserve source-specific schema and overrides.

The initial local catalog contains 3125 indexed presets (568 FOrca, 2015 official Orca and 542 separate Snapmaker profiles), with 821 cross-source identity collisions kept in namespaces. The official validator passes for the shipped official Snapmaker/OrcaFilamentLibrary bundles but rejects the imported catalogs. Reported errors include unindexed library files and vendor-specific auxiliary JSON recognized differently by the official validator. These failures require adapters and complete preset-loader checks; no imported catalog has been promoted into shipped resources.
